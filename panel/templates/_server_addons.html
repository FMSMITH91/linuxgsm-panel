    {% call fold("How add-ons run", id="ad-help", cls="mt-2") %}
      
    
        
  • Each add-on runs in a rootless Podman container as this server's account: no root daemon, no added privileges, a read-only system and capped memory.
    • 
        
  • Installing the first add-on on a host installs Podman from Ubuntu and lets the account's services run while nobody is signed in, so add-ons start again after a reboot.
    • 
        
  • An add-on's network is locked to what it needs: the game's RCON port and its database. On Ubuntu 26.04 it reaches nothing else. On Ubuntu 24.04 it can't reach the internet or other machines either, but a service listening on one of this host's own addresses (its Tailscale address, say) stays reachable.
    • 
        
  • B3 uses one of this server's databases from the Databases tab, and no other add-on may use the same one. IW4MAdmin keeps its own database (SQLite) in its folder.
    • 
        
  • An add-on's folder is in the server's home folder, so the server's backups include it.
    • 
        
  • An add-on's web page listens on this host's own address only (127.0.0.1); no port is opened for it. Open shows it through the panel, in a new tab, kept apart from the panel's own pages: it can't read the panel's sign-in or act for you on the panel. The link works only while you are signed in and may open add-on pages.
    • 
        
  • BlueMap reads the Minecraft world read-only and reaches nothing at all: Minecraft's client file it needs is downloaded by this host before it starts, once you accept Mojang's EULA.
    • 
        
  • Removing an add-on deletes its container, image and files. A database from the Databases tab is kept; an add-on's own data goes with it.
    • 
        
  • New versions of an add-on come with panel updates: after one, its card offers Update, and nothing changes until you press it.
    •
